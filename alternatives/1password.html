Free 1Password alternative: 1PasswordIsDead

Last reviewed October 26, 2026 · License: Apache-2.0 · Source on GitHub

1PasswordIsDead is an experimental, open-source password vault that encrypts everything in your browser and stores it only in that browser. It has a password generator, one-time codes and a password health check, but no sync, no browser extension and no account recovery. It has not been independently security audited, so treat it as a learning tool or a home for low-stakes secrets, not as the only copy of anything important.

What 1Password does, and what 1PasswordIsDead covers

1Password is a mature, cross-platform password manager. Your vaults sync between desktop, mobile and browser apps, the browser extension fills logins and passkeys, and you can share vaults with family or colleagues. Its key derivation combines your account password with a separate Secret Key generated on your device, and the company publishes third-party security assessments.

1PasswordIsDead is a single-browser vault. You create it with a master password, then store logins (with optional one-time-code secrets), payment cards and secure notes. You can search, tag and favorite items, reveal or copy secrets, generate random passwords or passphrases, and run an audit that lists weak, reused and year-old passwords. Filling a login means pressing copy buttons for the username, password and current code, then pasting.

How the security works

This is taken from the project's SECURITY.md and checked against its source code.

  • Key derivation: your master password goes through PBKDF2-HMAC-SHA256 with 600,000 iterations and a random 16-byte salt, producing an AES-256-GCM key. The browser's WebCrypto API creates the key as non-extractable.
  • What is encrypted: the whole vault, including titles, usernames, URLs and notes, is one JSON document. Every save encrypts it with a fresh random 96-bit IV. The format version, iteration count and salt are bound in as authenticated data, so tampering with them makes decryption fail.
  • What is stored, and where: only the encrypted blob and your auto-lock setting are written to the browser's localStorage. Nothing about the vault is sent to the site's server. Signing in to the website identifies you to the site but never unlocks the vault.
  • In memory: the master password and key are held only while unlocked, and are dropped on lock, auto-lock (1 to 60 minutes idle), sign-out or reload.
  • Breach check: optional and manual. It sends only the first five hex characters of a password's SHA-1 hash to the Have I Been Pwned range API.
  • Audit status: no independent security audit has been done.

The project is open about what it does not protect against: malware or a malicious browser extension, weak master passwords (PBKDF2 slows guessing but is not memory-hard), and other scripts on the same web origin. The hosted copy shares the yourappisdead.com origin with other apps, so for anything real the project recommends running your own copy on its own domain.

What it costs

As of October 2026, 1Password's pricing page lists Individual at US$3.99 a month and Families (five people) at US$5.99 a month, both billed yearly, with lower first-year prices offered to new customers. Business plans are priced separately, and a 14-day free trial is offered; there's no permanent free plan.

1PasswordIsDead is free. Self-hosting costs only your own hosting, and since the vault is stored in the browser, the server needs no database for it.

How to switch from 1Password

  1. Read SECURITY.md first and decide which secrets you are comfortable keeping in an unaudited tool.
  2. In the 1Password desktop app, export your data as CSV. The export is unencrypted, so do this on a trusted computer.
  3. Create a vault in 1PasswordIsDead with a long passphrase you won't forget. There is no reset.
  4. In Settings → Import CSV, choose the file. The importer recognizes common column names (title or name, url, username, password, notes, tags or folder) and imports logins only.
  5. Re-enter cards, notes and one-time-code secrets by hand, since the CSV importer doesn't bring those across.
  6. Delete the plaintext CSV, then use Download encrypted backup and keep that file somewhere safe.

Running it yourself

It's a Next.js and TypeScript app using the browser's built-in WebCrypto, with Firebase for site sign-in. Run npm ci, then npm run dev, and open http://localhost:3000/onepasswordisdead; a demo account is available in development. npm test runs unit tests. For real use, deploy it on a dedicated domain with no other apps.

Limitations

  • Not independently audited, and described by its author as experimental.
  • One browser only. Clearing site data, or the browser evicting storage, deletes the vault unless you have a backup.
  • No recovery: a forgotten master password means the data is gone.
  • No extension, autofill, passkeys, sharing or emergency access.
  • The demo account uses a published master password and sample data; never put real secrets in it.

FAQ

Can the site's operator read my passwords?

The vault is encrypted in your browser and never sent to the server. The remaining risk is code: a malicious or compromised script served on the same origin could read an unlocked vault, which is why self-hosting on a dedicated domain is recommended.

What is in the encrypted backup?

The same ciphertext stored in your browser. It's useless without your master password, and you can restore it when creating a vault in another browser.

Why PBKDF2 and not Argon2?

PBKDF2 is built into browsers' WebCrypto API; Argon2 and scrypt are not. The trade-off is that PBKDF2 is less resistant to GPU guessing, so a long master password matters more.

Can I export everything back out?

Yes. Besides the encrypted backup, there's a plaintext CSV export, with a warning to delete the file when you're done.
