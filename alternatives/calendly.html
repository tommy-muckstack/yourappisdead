Free Calendly alternative: CalendlyIsDead

Last reviewed October 26, 2026 · License: Apache-2.0 · Source on GitHub

CalendlyIsDead is a free, open-source scheduling app. You publish a booking page, invitees pick a slot that is checked against your real calendars, and the meeting is added to your calendar with a confirmation email. It handles one-on-one, group and team scheduling, and you can use the hosted copy or run it on your own servers.

What Calendly does, and what CalendlyIsDead covers

Calendly exists to end the "does Tuesday work?" email chain. You set the hours you are available, create event types such as a 30-minute intro call, and share a link. Invitees only see times that are free on your connected calendars. Around that core, Calendly sells team scheduling, lead routing, reminders, payments and reporting, and it has added meeting notes and AI features on top.

CalendlyIsDead rebuilds the scheduling part. Each event type has a duration, location, buffer time before and after, minimum notice, a booking window, optional daily and weekly caps, custom questions for the invitee and an optional page to redirect to after booking. Availability is a weekly schedule with date overrides and a time zone. The app reads busy times from Google Calendar, Outlook or Microsoft 365, and iCloud (over CalDAV). You choose which calendars count as conflicts and which one receives new bookings. Invitees get an email with an .ics file and links to reschedule or cancel.

For teams, there are collective events where everyone must be free, round robin that spreads meetings evenly or by priority, managed event types that are copied into each member's account with locked fields, and group events with a seat limit. Workflows send email or SMS reminders and follow-ups. Routing forms ask a few questions and send people to the right event type, a URL or a message. You also get meeting polls, single-use links, embeddable widgets, brand colors and logos, and an analytics page. A separate email assistant reads a pasted email thread and drafts a reply with booking links. It never sends mail on its own.

What it costs

As of October 2026, Calendly's pricing page lists a Free plan limited to one event type and one calendar connection, Standard at $10 per seat per month and Teams at $16 per seat per month (the discounted rates shown for yearly billing), and Enterprise starting at $15,000 a year. A five-person team on Teams pays $960 a year.

The hosted CalendlyIsDead at yourappisdead.com costs nothing and has no paid tiers. If you self-host, you pay your own infrastructure: a Postgres database, a host for a Next.js app, and an email provider. Optional services add their own usage costs, such as Twilio per SMS and Stripe's normal card fees on paid bookings.

How to switch from Calendly

  1. Write down each Calendly event type: name, URL slug, length, location, questions, buffers and limits. There is no importer, so you will recreate them by hand.
  2. Sign in to CalendlyIsDead and open Calendars. Connect Google, Outlook or iCloud, tick the calendars to check for conflicts, and pick the one new bookings go to.
  3. Set your weekly hours and time zone under Availability, and add date overrides for holidays or travel.
  4. Create your event types. Reusing the same slugs makes it easy to swap links later.
  5. Rebuild any reminders under Workflows and any qualification questions under Routing forms.
  6. Replace the links on your website and email signature. For embeds, generate a new snippet in the Embed section of the app.
  7. Keep Calendly running until meetings already booked there have happened. Those bookings are not moved over, and their reschedule links still point at Calendly.

Running it yourself

The app is built with Next.js, Postgres through Drizzle (Neon in production, an embedded PGlite database locally) and Firebase Authentication for sign-in, and it is set up for Vercel. To try it, run npm install and then npm run dev. You get a seeded demo host and a booking page at /demo/30min without any keys, and booking emails are printed to the server log until you set RESEND_API_KEY.

For production you set DATABASE_URL, AUTH_SECRET, the Firebase variables, OAuth clients for Google and Microsoft calendars, and CRON_SECRET for the job that sends workflow messages every five minutes. npm run db:migrate applies the schema. Unit and integration tests run with npm test, browser tests with npm run e2e.

Limitations

  • No import from Calendly, and existing Calendly bookings stay there.
  • When self-hosting, every integration needs your own credentials: Google and Microsoft OAuth apps, a Zoom server-to-server app, Stripe, Twilio and Resend. Without them the app falls back to stand-ins such as a labelled demo meeting room, a simulated checkout and SMS that is only logged.
  • No notetaker, CRM integrations, Zapier, outgoing webhooks or SSO.
  • The email assistant only drafts replies. It uses a built-in parser unless you supply your own API key for an OpenAI-compatible model.
  • Support is through GitHub issues, with no service-level agreement.

FAQ

Do my invitees need an account?

No. People booking a meeting just open your link, pick a time and enter their name and email. Only hosts sign in.

Can I import my event types from Calendly?

Not yet. You recreate them, which usually takes a few minutes per event type if you note the settings first.

Does it work with Outlook and Microsoft 365?

Yes. It connects through a Microsoft app registration to read busy times and write new bookings. iCloud works through an Apple app-specific password.

Can I charge for meetings?

Yes. Set a price on an event type and connect your own Stripe account. The slot is held for 30 minutes while the invitee pays, and confirmations only go out once payment completes. The money goes straight to your Stripe account.

Is the hosted version really free?

Yes. Every feature that exists is available to everyone. If you self-host, the only costs are your own hosting and any paid services you connect.
